# Техническое задание

Автор: Волков Лев Геннадьевич. Тема: разработка веб-сервиса аренды недвижимости.

Разрабатываю веб-приложение для размещения и поиска объявлений о долгосрочной аренде недвижимости, чтобы пользователи могли находить жильё и связываться с владельцами через заявки. Основные пользователи: арендаторы, владельцы недвижимости и администратор.

| Функция | Описание | Приоритет | Статус |
| --- | --- | --- | --- |
| Регистрация и вход | Имя, email, пароль, cookie-сессия | Высокий | Реализовано |
| Каталог | Только доступные объекты активных владельцев | Высокий | Реализовано |
| Поиск | Подстрока в заголовке и описании | Высокий | Реализовано |
| Фильтры | Город целиком, тип жилья, верхняя цена | Высокий | Реализовано |
| Сортировка и пагинация | Новизна, цена; 6 записей на страницу | Средний | Реализовано |
| CRUD объявлений | Создать, просмотреть, изменить, удалить | Высокий | Реализовано |
| Заявки | Дата заселения, сообщение, статусы | Высокий | Реализовано |
| Администрирование | Объявления, статистика, блокировка | Высокий | Реализовано |
| Адаптивность | 390, 768, 1280 CSS px | Высокий | Проверено |
| OpenAPI | Схема API и Swagger | Средний | Реализовано |

Гость читает публичные объявления без телефона. Пользователь читает телефон после входа и управляет только своими объявлениями. Администратор управляет всеми объявлениями; роль не задаётся при регистрации. Принять/отклонить заявку может только владелец объекта; отменить ожидающую заявку — её автор.

Нефункциональные требования: локальное чтение каталога — целевой p95 менее 500 мс на учебных данных; параметры SQL отделены от запросов; пароли хешируются scrypt; у cookie флаг HttpOnly; изменяющие запросы защищены CSRF и проверкой Origin. При развёртывании в интернете требуется HTTPS и COOKIE_SECURE=1. Интерфейс работает без внешних шрифтов и CDN, поля имеют подписи, ошибки выводятся текстом. Не заявляется аудит соответствия WCAG.

Ограничения: один серверный процесс, локальный файл SQLite, небольшой учебный объём данных, без оплаты, карт, загрузки фотографий, почтовых уведомлений и заключения договоров. Иллюстрации карточек сделаны CSS. Публичный хостинг не настроен. Перед использованием с реальными данными нужны резервное копирование, централизованное ограничение запросов и дополнительный аудит безопасности.

Сценарии приёмки: регистрация → создание → изменение → удаление объявления; поиск и фильтрация каталога; арендатор отправляет заявку → владелец принимает → объект исчезает из доступного каталога; попытка изменить чужое объявление возвращает 403; администратор блокирует пользователя → его сессии удаляются, объявления скрываются.
