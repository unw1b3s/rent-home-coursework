# Установка и развёртывание

## Локально

Команды приведены в README. Требуются Python 3.14 и pip, интернет нужен только при установке пакетов. Сервер и база после установки работают без внешних сервисов. База создаётся по пути `data/rent.db`; перенести данные можно копированием этого файла при остановленном сервере. Рабочая БД не входит в Git.

Переменные читаются из окружения, `.env.example` служит образцом и автоматически не загружается:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| DATABASE_PATH | data/rent.db в проекте | Путь SQLite |
| COOKIE_SECURE | 0 | 1 разрешает cookie только через HTTPS |
| APP_ORIGIN | Адрес входящего запроса | Допустимый Origin изменяющего запроса |

Для Linux/macOS: `export DATABASE_PATH=./data/rent.db`. Для PowerShell: `$env:DATABASE_PATH='./data/rent.db'`. При изменении переменных сервер нужно перезапустить. В локальном браузере используйте один адрес: 127.0.0.1 либо localhost, чтобы не разделять cookie между хостами.

## Собственный администратор без seed

Зарегистрируйте свой аккаунт в пустой базе, остановите сервер и выполните из корня проекта:

```bash
python -c "import sqlite3; db=sqlite3.connect('data/rent.db'); db.execute('UPDATE users SET role=? WHERE email=?', ('admin','YOUR_EMAIL')); db.commit(); db.close()"
```

Замените `YOUR_EMAIL` на email зарегистрированного аккаунта. Если DATABASE_PATH переопределён, укажите фактический путь. Затем запустите сервер и войдите заново. Публичный API не позволяет назначать роли.

## Docker и сервер Linux

`docker compose up --build -d` собирает контейнер. Для демонстрации выполните `docker compose exec web python -m app.seed`. Код запускается непривилегированным пользователем, файл БД остаётся в отдельном томе. В compose порт привязан к loopback, чтобы внешний доступ проходил через reverse proxy.

На VPS установите Docker, скопируйте проект и используйте compose. Для внешнего HTTPS-доступа настройте домен, сертификат и Nginx по образцу `deploy/nginx.conf.example`. Перед запуском задайте `COOKIE_SECURE=1` и `APP_ORIGIN=https://ваш-домен`. Откройте снаружи только 80/443, а 8000 оставьте локальным. После изменения переменных пересоздайте контейнер командой `docker compose up -d`.

Проверьте `/api/health`, регистрацию, сохранение объявления и вход после перезапуска. Убедитесь, что у cookie есть Secure и что HTTP перенаправляется на HTTPS. Docker-образ собран и запущен; через HTTP проверены основные операции и сохранение данных после перезапуска. Результаты находятся в docker-results.txt. Публичное размещение с доменом и HTTPS не выполнялось.

## Резервная копия и обновления

Для локальной копии остановите Uvicorn и скопируйте `data/rent.db` в отдельный каталог с датой. Для Docker остановите сервис `docker compose stop web`, затем используйте временный контейнер для копирования тома либо штатный backup SQLite. Не копируйте изменяемую БД побайтово во время записи.

Перед обновлением сохраните код и БД. Сейчас поддерживается только версия схемы 1; неизвестная версия останавливает запуск. Новые миграции надо добавлять последовательно. Для восстановления верните совместимый код и копию БД при остановленном сервере.

## Частые проблемы

- `No module named fastapi`: активируйте .venv и установите requirements.txt тем же Python.
- Порт занят: используйте `--port 8001`, открывайте соответствующий адрес.
- Ошибка CSRF: обновите страницу и войдите снова; не смешивайте localhost и 127.0.0.1.
- Пустой каталог: выполните seed в пустой базе либо создайте объявление. Seed намеренно не перезаписывает существующих пользователей.
- Cookie не сохраняется локально: отключите COOKIE_SECURE при обычном HTTP.
- 429 при входе: подождите 5 минут после неудачных попыток.
