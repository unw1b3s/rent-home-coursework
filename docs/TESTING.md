# Тестирование

Дата проверки: 20.10.2026. Модульные и интеграционные тесты запускаются pytest через FastAPI TestClient с отдельным временным SQLite-файлом для каждого теста. Отчёт покрытия измеряет строки Python; JavaScript и CSS не входят в метрику.

Команды:

```bash
python -m pip install -r requirements-dev.txt
coverage run --source=app -m pytest -q
coverage report
```

Итог: **24 passed**, **99%**. Сохранён полный вывод в `test-results.txt`. Starlette выводит предупреждение об устаревании httpx-адаптера TestClient; оно не является падением теста. Обновление тестового клиента можно выполнить отдельно после проверки совместимости зависимостей.

## Проверка через браузер

1. Зарегистрировать нового пользователя — личный кабинет открыт, аккаунт создан.
2. Создать объявление «Квартира для учебной проверки» — карточка появилась в кабинете.
3. Изменить цену с 32000 на 31000 — сохранено; удалить с подтверждением — карточка исчезла.
4. Отправить заявку на объект владельца с заселением 01.12.2026 — статус «Ожидает ответа».
5. Войти как owner@example.com и принять заявку — статус «Принята», объект перестал показываться среди доступных.
6. Войти как admin@example.com — таблицы объявлений и пользователей, статистика доступны.
7. Открыть каталог на ширине 390, 768 и 1280 CSS px — карточки перестраиваются; на 390 и 768 проверено отсутствие горизонтального переполнения.

Скриншоты этих сценариев сохранены в `screenshots/`. Это ручная E2E-проверка с помощью управления браузером, отдельного автоматизированного браузерного тестового пакета в проекте нет. Учебные записи проверки после неё удалены, восемь исходных объявлений снова доступны.

## Отклик

`python scripts/benchmark.py` при запущенном сервере выполняет 5 прогревочных и 100 последовательных запросов к GET /api/listings. Среднее, p95 по правилу ближайшего ранга и максимум записываются в `benchmark.json`. Это проверка локального отклика на небольшом каталоге, без конкурирующих пользователей и сетевых задержек. Она не доказывает производительность публичного сервера.

При заключительной проверке выявлен и исправлен один дефект: администратор не мог открыть для редактирования объявление заблокированного владельца. Обработчик теперь разрешает административный просмотр, при этом гостю возвращает 404; сценарий включён в интеграционный тест. После исправления критические дефекты в пройденных сценариях не обнаружены. Полное число промежуточных ошибок разработки не подсчитывалось. Docker-сборка, HTTP-сценарии в контейнере и сохранение БД после перезапуска проверены; подробности — docker-results.txt. Внешний HTTPS-хостинг и полноценный аудит безопасности не проверены.
