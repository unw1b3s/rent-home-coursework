# Архитектура и база данных

Приложение состоит из клиента на чистом JavaScript, JSON REST API FastAPI и реляционной базы SQLite. Клиент и API обслуживаются одним сервером, отдельный CORS-доступ не включён. Клиентские маршруты находятся после `#`, перезагрузка карточки не требует отдельной настройки серверных путей.

![Компоненты](architecture.png)

`main.py` содержит обработчики и проверку прав, `schemas.py` — Pydantic-модели входных данных, `security.py` — хеширование, `db.py` — управление подключениями. Для небольшой курсовой обработчики обращаются к SQL напрямую, отдельный слой Repository не добавлен. Повторяемые проверки объекта и владельца вынесены в функции. Клиент хранит текущего пользователя и CSRF-токен в памяти, а данные перечитывает из API после изменений.

![ER](er-diagram.png)

Редактируемый исходник: [er-diagram.drawio](er-diagram.drawio).

| Таблица | Назначение | Ключевые ограничения |
| --- | --- | --- |
| users | Аккаунты и роли | PK id, UNIQUE email, CHECK role/active |
| sessions | Сессии входа | PK token_hash, FK user_id, срок жизни |
| property_types | Типы недвижимости | PK id, UNIQUE name |
| listings | Объявления | FK owner_id/type_id, CHECK цены/площади/комнат |
| rental_requests | Заявки арендаторов | FK listing_id/tenant_id, CHECK status |

Связи 1:N: пользователь → объявления, пользователь → сессии, пользователь → заявки, тип → объявления, объявление → заявки. Заявки образуют связь пользователей и объектов с дополнительными атрибутами. Частичный уникальный индекс не допускает двух активных заявок одного арендатора на один объект. Удаление объявления каскадно удаляет его заявки. Пользователи в интерфейсе не удаляются, а блокируются.

В третьей нормальной форме не дублируются имя владельца в объявлении, название типа в каждой записи и заголовок объекта в заявке. Эти сведения извлекаются JOIN-запросами. Цена — целое число рублей в месяц, площадь — REAL в м², даты заселения — ISO YYYY-MM-DD, технические метки времени SQLite — UTC. Роль владельца определяется связью owner_id; отдельной роли landlord нет, один пользователь может и снимать, и сдавать жильё.

Миграция `sql/001_initial.sql` устанавливает `PRAGMA user_version=1`. При старте версия 0 мигрирует до 1, версия 1 используется повторно, неизвестная версия отклоняется. Для последующих версий надо добавлять отдельные SQL-миграции и последовательные переходы, предварительно сделав резервную копию. FK включаются на каждом подключении.

Принятие заявки использует `BEGIN IMMEDIATE`: проверка доступности, изменение объявления, отклонение других ожидающих заявок и принятие выбранной заявки выполняются одной транзакцией. При ошибке происходит rollback. Это не календарь посуточного бронирования: проект рассчитан на долгосрочную аренду одного объекта одному арендатору.
