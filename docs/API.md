# REST API

Полная схема: [openapi.json](openapi.json); интерактивная документация — `/docs` запущенного приложения. Формат тел — `application/json`. Браузер сам отправляет HttpOnly cookie `session`, выданную при регистрации или входе. Для POST/PUT/PATCH/DELETE после входа требуется заголовок `X-CSRF-Token`; его значение возвращается при входе и в `/api/auth/me`. Публичным входу и регистрации CSRF-токен не нужен: для них проверяются Origin и JSON Content-Type.

| Метод и путь | Назначение | Доступ |
| --- | --- | --- |
| GET /api/health | Проверка БД | Все |
| POST /api/auth/register | Зарегистрироваться | Все |
| POST /api/auth/login | Войти | Все |
| GET /api/auth/me | Пользователь и CSRF | Вошедший |
| POST /api/auth/logout | Завершить сессию | Вошедший |
| GET /api/types | Типы жилья | Все |
| GET /api/listings | Поиск и каталог | Все |
| GET /api/listings/{id} | Карточка | Все; телефон после входа |
| POST /api/listings | Создать | Вошедший |
| PUT /api/listings/{id} | Полностью обновить | Владелец или админ |
| DELETE /api/listings/{id} | Удалить | Владелец или админ |
| GET /api/my/listings | Свои объявления | Вошедший |
| POST /api/listings/{id}/requests | Отправить заявку | Вошедший, кроме владельца |
| GET /api/my/requests | Свои и входящие заявки | Вошедший |
| PATCH /api/requests/{id} | Изменить статус | Арендатор или владелец по действию |
| GET /api/admin/summary | Число пользователей, объявлений, заявок | Админ |
| GET /api/admin/users | Пользователи | Админ |
| PATCH /api/admin/users/{id} | active=true/false | Админ |
| GET /api/admin/listings | Все объявления | Админ |

Каталог: `q` (подстрока), `city` (полное название), `type_id` (1..4), `max_price`, `sort` (`newest`, `price_asc`, `price_desc`), `page` (от 1), `page_size` (1..50, по умолчанию 6). Ответ: `{items: [...], total: 8, page: 1, page_size: 6}`. Административные списки имеют `page` и `page_size` (по умолчанию 20, максимум 100), ответ `{items: [...], total: ...}`.

Объявление: `title, description, type_id, city, address, price, rooms, area, phone, status`. `id`, `owner_id`, `created_at`, `owner_name`, `type_name` возвращает сервер. Передавать их при создании нельзя. PUT получает все редактируемые поля; частичное изменение объявления не реализовано.

Заявка создаётся телом `{"move_in":"2026-12-01","message":"Хочу снять квартиру"}`. Дата должна быть не раньше текущей даты сервера. Новая заявка имеет статус `pending`. Владелец переводит её в `accepted` или `rejected`, арендатор — в `cancelled`. Других переходов нет. После отмены/отклонения можно отправить новую заявку. При повторной публикации сданного объекта прежняя принятая заявка помечается `cancelled`; это завершение связи в упрощённой учебной модели, без учёта договоров.

Пример входа:

```bash
curl -c cookies.txt http://127.0.0.1:8000/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"owner@example.com","password":"demo12345"}'
```

Скопируйте `csrf_token` из JSON. Затем:

```bash
curl -b cookies.txt http://127.0.0.1:8000/api/listings \
  -H 'Content-Type: application/json' \
  -H 'X-CSRF-Token: ВСТАВЬТЕ_ТОКЕН' \
  -d '{"title":"Квартира у парка","description":"Однокомнатная квартира с мебелью для долгосрочной аренды.","type_id":1,"city":"Москва","address":"ул. Учебная, д. 5","price":35000,"rooms":1,"area":38,"phone":"+7 000 000 00 01","status":"available"}'
```

Ошибки: 400 — недопустимое действие; 401 — нет сессии/неверный вход; 403 — нет прав/CSRF/Origin; 404 — объект не найден; 409 — занятый email, повторная активная заявка или конфликт статуса; 413 — заявленная длина тела более 20 КБ; 415 — Content-Type не JSON; 422 — неверные поля; 429 — 10 неудачных входов за 5 минут с одного IP. Текст ошибки находится в `detail`. Успешное удаление/выход — 204, создание — 201, чтение и обновление — 200.

Ограничение длины в приложении проверяет Content-Length; на публичном сервере дополнительно нужен лимит Nginx, поскольку потоковый chunked-запрос не ограничивается этим заголовком. Ограничитель входа хранится в памяти одного процесса.
